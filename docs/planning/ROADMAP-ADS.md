## 1. 背景与结论

**核心结论：不存在单一技术能屏蔽全部广告，必须采用分层防御（Defense in Depth）。**

现有客户端只覆盖「开屏/弹窗的跳过按钮点击」这一层（L1）。要扩大覆盖面，需按广告形态拆分为五个能力层，每层参考一个成熟开源项目，**各层独立发布、互不阻塞**。

## 2. 五层防御架构与参考项目

| 层 | 能力 | 解决什么 | 代表参考项目 |
| --- | --- | --- | --- |
| **L1 无障碍点击层** | 遍历节点树点击「跳过/关闭」按钮 | 开屏、插屏、各类弹窗 | [GKD](https://github.com/gkd-kit/gkd)（选择器+订阅）、[SKIP](https://github.com/GuoXiCheng/SKIP)、[TapClick](https://github.com/haoweishow/TapClick)、本项目现有引擎 |
| **L2 网络过滤层** | DNS/hosts 拦截广告请求 | Banner、信息流素材、联盟广告请求 | [AdGuard Home](https://github.com/AdguardTeam/AdGuardHome)、[AdAway](https://github.com/AdAway/AdAway)、AWAvenue-Ads-Rule（规则集）、本地 VpnService DNS 形态 |
| **L3 Hook 层**（可选 Root） | Hook 广告 SDK / 传感器 | 摇一摇、扭一扭跳转、贴片跳过 | [fuck_shake](https://github.com/0x0hiii/fuck_shake)（防摇一摇，LSPosed）、[AdClose](https://github.com/Siroko/AdClose)、LSPosed 框架 |
| **L4 系统/通知层** | 通知过滤、系统级设置引导 | 推送通知广告、悬浮窗治理、锁屏/负一屏 | [push-filter](https://github.com/miuir/push-filter)、[mnblocker](https://github.com/XiaoYieXianCheng/mnblocker)、厂商 ROM 自带开关 |
| **L5 规则生态层** | 订阅分发 + 社区共建 + 快照工具 | 让 L1 规则持续覆盖新 App | GKD 订阅机制（`gkd-subscription` topic）、SKIP 的 YAML 订阅 + PR 共建、GKD inspect 快照审查 |

> 当前仅 L1 落地；L2/L3 未获批、未启用；L4 已提前交付「厂商 ROM 跳转 + 磁贴」骨架，通知过滤本体未做。

## 3. 能力边界与合规前提

### 3.1 范围边界

原「明确不做」边界清单已于 2026-10-10 解除。原排除项（激励视频代跳、内容型广告删除、短信/商店/搜索广告、视频贴片/Draw）不再作为范围限制，是否承接按第 4 节矩阵与后续版本排期决定。

> 边界变更的外部证据、风险评估与门禁验证记录见 [ROADMAP-ADS-VERIFY.md](ROADMAP-ADS-VERIFY.md)。

### 3.2 合规前提（Phase 0 评审项）

- **边界声明张力**：`ROADMAP.md`「明确不做的」写的是「只点击界面已有跳过按钮，不拦截/破解广告内容」。**L2 DNS 过滤与该条款存在张力**，启用前必须修订声明并明确：L2 仅拦截已知广告域名的网络请求、不改写/解密任何内容、默认关闭；
- **不正当竞争先例**：吸收「李跳跳」诉讼先例——仅点击 UI 已展示的按钮、不上架应用商店、免责声明醒目；
- **发布闸门**：合规评审未通过前，L2/L3 不进入发布分支。

## 4. 广告类型 → 分层覆盖矩阵

矩阵按**「是否有可点击的关闭节点」**这一技术判据组织，而不是按清单目录逐条罗列——否则 60+ 行里绝大多数会退化成「不做」，失去指导意义。未单列的条目按 4.3 处理。

### 4.1 覆盖矩阵

| 广告类型（对应清单章节） | 层 | 方案 | 覆盖度 |
| --- | --- | --- | --- |
| 开屏广告（一.1） | L1 | 关键词 + ViewID 点击（现有能力） | ✅ 高 |
| 插屏/新插屏（一.3/4） | L1 | GKD 式选择器规则点关闭按钮 | ✅ 中高 |
| 弹窗类、悬浮窗（一.2 部分、二.2） | L1 | 选择器规则 + SafetyGuard 护栏 | ✅ 中 |
| 视频角标（一.13） | L1+L2 | 角标通常带关闭控件 → 选择器点关；素材请求 L2 拦 | ✅ 中 |
| Banner（一.2）、信息流/Draw/沉浸式（一.5/6/7）、下拉刷新（一.22） | L2 | DNS 拦广告素材域名 | ⚠️ 中（native 广告可能留白） |
| 轮播（一.17）、原生模板（一.10）、富媒体（一.16）、上下文/情境（三.4） | L2 | 无可点节点，只拦素材/上报域名 | ⚠️ 低中 |
| 联盟广告（七，穿山甲/优量汇/快手） | L2 | **按广告 SDK 域名族拦截**——国内占比最高且域名稳定，性价比最高的靶子 | ✅ 中高（待 Phase 0） |
| 程序化广告（七，RTB/DSP） | L2 | 竞价域名每次变化，无法用静态规则覆盖 | ❌ 低（**如实告知不可拦**） |
| 激励视频（一.8）、全屏视频（一.11）、贴片（一.12）、导视（一.18） | L1+L2 | 倒计时后出现跳过/关闭控件的样式由 L1 选择器点击（M5）；素材域名 L2 拦（部分破图） | ⚠️ 中（激励视频代跳随 M5 交付；贴片仍仅破图） |
| 可试玩广告（一.14） | L2 | 试玩 Demo 需下载安装，L1 无解；仅拦落地页与追踪域名 | ❌ 低 |
| 音频广告（五） | L2 | 纯音频无可点节点，**UI 层完全无解**；仅能拦音频 CDN 与广告 SDK 域名 | ❌ 低 |
| 公告/小喇叭（一.19） | L2 | 滚动文字无关闭控件，L1 无解；仅破素材 | ❌ 低 |
| 摇一摇/扭一扭/滑动（九） | L3 | Hook 加速度/陀螺仪回调 | ✅ 高（需 Root） |
| 长按/画圈/3D 小手（九） | L3 | 同上，Hook 长按与手势分发回调 | ✅ 中高（需 Root） |
| 推送通知广告（二.1） | L4 | NotificationListener 过滤 + 黑名单 | ✅ 中高 |
| 锁屏/负一屏/系统通知栏（二.3/6/7） | L4 | 引导关闭厂商开关（按 ROM 维护路径库） | ⚠️ 中 |
| 浏览器弹窗（二.5） | L2+L1 | 浏览器自带拦截为主，L1 兜底 | ✅ 中 |
| 互动广告（一.15） | L2+L3 | 素材 L2 拦；滑/摇等互动跳转 L3 屏蔽 | ⚠️ 中（待 Phase 0） |
| 文字/超链接广告（一.21） | — | **不做**：点击即访问广告落地页，无关闭语义 | — |
| 积分墙/推荐墙（三.1/2） | — | **不做**：点击即触发下载安装，与「只点关闭按钮」边界冲突 | — |
| 短信广告（二.4） | — | 不做（系统短信 App 自带拦截） | — |
| 信息流/搜索/社交/直播/电商/应用商店内容型（四） | L2+L1 | 素材域名族拦截 + 商店开屏/弹窗选择器（M6 评估） | ⚠️ 待评估 |
| 交叉推广（三.6）、付费去广告（三.7） | — | 不适用：前者为同公司导流，后者是用户付费而非广告 | — |

### 4.2 穿山甲八式交叉校验

激励视频 ✅L2破图 / 全屏视频 ✅L2破图 / Draw 信息流 ✅L2 / 信息流 ✅L2 / 开屏 ✅L1高 / 插屏 ✅L1中高 / Banner ✅L2 / 互动广告 ⚠️L2+L3。

**八式中无一可由 L1 完整解决**（除开屏与插屏），这是分层结论最直观的佐证。

### 4.3 不纳入矩阵的维度

清单共 7 个维度，并非每一个都对应「可治理对象」。明确排除，避免矩阵虚胖与覆盖率口径失真：

| 维度 | 是否纳入 | 理由 |
| --- | --- | --- |
| 一 展示形式 / 二 触达渠道 / 三 交互变现 / 九 创新交互 | ✅ 纳入 | 直接对应界面上的可点节点或网络请求，是技术可治理对象 |
| 四 投放场景/平台 | ⚠️ 部分 | 仅当该场景产生可点广告位才纳入；纯平台内内容（社交/直播/电商/商店）纳入即「不做」 |
| 五 表现材质 | ⚠️ 仅纳入技术缺口 | 材质本身不是治理对象，但**音频**等无节点材质构成真实空白，故单列一行 |
| 六 计费方式（CPM/CPC/CPA…） | ❌ 不纳入 | **商业属性而非技术对象**：CPM 与 CPA 的广告在客户端完全同构，计费方式不改变任何技术手段。纳入只会把 60+ 行矩阵变成 70+ 行而无信息增量 |
| 七 投放逻辑 | ⚠️ 部分 | 联盟广告有稳定域名族（纳入 L2）；程序化 RTB 每次竞价域名变化，不可静态拦截（如实标注） |
| 八 激励视频进阶玩法 | ❌ 不纳入 | **商业机制而非技术对象**：再得激励/任务分段/额外任务都是诱导用户多看广告的运营手段，不构成独立可治理的广告类型 |

## 5. 分阶段计划

> **排期说明**：下文各 Phase 保留原始周次（2026-09 制定），**它表达的是依赖顺序，不是当前日历承诺**。实际节奏以第 6 节里程碑状态为准。

每个阶段统一按「做什么 / 交付物 / 验收 / 状态」四段描述。

### Phase 0 — 调研固化与合规评审（第 1~2 周，P0）

- **做什么**：固化能力边界与免责声明，完成 L2/L3 技术选型。
- **交付物**：《能力边界与免责声明 v2》（逐类型标注覆盖度，即第 4 节矩阵）；技术选型 ADR——L2 采用「本地 VpnService DNS（免 Root）」还是「外接 AdGuard Home」，L3 采用 LSPosed 模块还是独立 Root 方案。
- **验收**：边界声明定稿；L2/L3 启动获批。
- **状态**：**未完成**。已在 [Issue #84](https://github.com/LiYihai1121/qingqi/issues/84) 建档，评审进行中，L2/L3 保持未获批、未启用。

### Phase 1 — L1 无障碍点击层（第 3~8 周，P0 核心）

> 详细技术方案（文法规范、匹配算法、协议 v2、改动清单、测试计划）见 [DESIGN-PHASE1-SELECTOR.md](DESIGN-PHASE1-SELECTOR.md)。

- **做什么**：参考 GKD / TapClick 升级现有引擎（关键词 + ViewID 双通道是覆盖瓶颈），分五步交付：

| 步骤 | 能力 | 状态 |
| --- | --- | --- |
| A/B | **选择器引擎**：父子/兄弟节点关系匹配（类 CSS 选择器子集：`vid`/`text`/`desc` + 3~4 种关系运算符），纯 Kotlin 零依赖 | ✅ 已交付（M1a） |
| C | **规则热扩展**：复用 v1 协议（ETag/304 + JobScheduler 同步），`schemaVersion: 2` 增加选择器表达式字段，保持 v1 客户端兼容 | ✅ 已交付（M1b） |
| D | **点击结果校验**：点击后 500ms 内若跳转外部 Intent / 页面异常切换，回退并将规则加入本地黑名单；SafetyGuard 硬编码黑名单不可被云规则覆盖 | ✅ 已交付（M1b） |
| E | **快照工具**：App 内导出当前节点树（参考 GKD inspect），分享文本二分查找截断至 ≤ 96 KB（`truncated=true` 标记） | ✅ 已交付（M1c） |
| F | **Top 30 规则 + 真机验收 + 规则审核通道** | ⏳ 未启动（M1d） |

- **验收**：工程门禁（CI 全绿 + 契约夹具双端一致 + 劫持场景单测绿）**已通过**；真机指标（Top 30 App 开屏跳过率 ≥ 95%、误触率 = 0、`findTarget` p99 < 8ms）随 M1d 验收。
- **状态**：**收尾中**，仅剩步骤 F。

### Phase 2 — L2 网络过滤层（第 5~10 周，P1，可与 Phase 1 并行）

参考 AdAway / AWAvenue-Ads-Rule：

1. **方案 A（推荐，免 Root）**：本地 VpnService 做 DNS 过滤，规则源直接订阅成熟规则集（AWAvenue 等，不自造轮子）；**默认关闭**，仅拦截明确广告域名；
2. **方案 B（轻量备选）**：不内置 VPN，文档引导自建 AdGuard Home / 改 DNS，本项目只做规则聚合与健康检查；
3. 服务端新增 `GET /api/v1/filter-rules` 路由，复用现有鉴权/限频/ETag 基建。

- **验收**：Top 20 App 的 Banner/信息流素材拦截率 ≥ 70%；VPN 关闭时零开销；正常业务域名零误伤（冒烟测试框架扩展回归集）。
- **状态**：**受阻**，待 Phase 0 合规评审获批。

### Phase 3 — L3 防互动跳转 Hook 层（第 9~13 周，P1，Root 可选）

参考 fuck_shake / AdClose（LSPosed）：

1. 独立 LSPosed 模块：对广告包名的加速度/陀螺仪回调投递空实现 → 屏蔽摇一摇/扭一扭跳转；
2. 可选评估：Hook 穿山甲/优量汇 SDK 落地页 `startActivity` 拦截（风险高，放后续决策）；
3. **定位为可选组件**：无 Root 用户提示不可用，主流程（L1+L2）不依赖。

- **验收**：Top 10 摇一摇广告 App 实测跳转触发率 0；模块停用后无残留。
- **状态**：**受阻**，待 Phase 0 合规评审获批。

### Phase 4 — L4 通知与系统层（第 11~14 周，P2）

参考 push-filter / mnblocker：

1. NotificationListenerService 过滤营销通知（「推广关键词 + 非联系人」启发式），默认仅静默、可恢复；
2. 悬浮窗广告：引导关闭「显示在其他应用上层」权限（无障碍无权代管，只能引导）；
3. 锁屏/负一屏/厂商推送：维护主流 ROM（小米/华为/OPPO/vivo）关闭路径图文库，设置页一键跳转。

- **验收**：通知过滤误杀率 < 1%（白名单机制），提供手动恢复入口。
- **状态**：**部分交付**。第 3 条的「厂商 ROM 关闭路径 + 一键跳转」骨架已上线（`VendorKeepAlive` 厂商入口表 + `KeepAliveNavigator` 逐级降级 + `<queries>` 可见性声明 + `SkipTileService` 磁贴）；**剩余范围**：通知过滤本体 + 锁屏/负一屏图文库 + 白名单恢复入口。

### Phase 5 — L5 规则生态与运营（第 7 周起持续，P1）

参考 GKD 订阅 topics / SKIP PR 共建：

1. 管理后台增加**快照提交通道**：用户一键上传节点快照 → ADMIN_TOKEN 审核 → 入库下发；
2. 规则库按包名版本化，失效自动降级（扩展现有 schemaVersion 校验）；
3. 文档：规则编写指南 + 覆盖度矩阵公示。

- **验收**：规则月均新增 ≥ 20 条；12h 自动同步链路可用（现有 SyncJobService）。
- **状态**：**未启动**（快照采集能力已由 M1c 具备，缺审核通道与运营流程）。

## 9. 对用户公示口径

- **较好解决 ≈ 45%**：开屏、插屏、弹窗、推送通知、锁屏可关项、摇一摇、Banner/信息流素材拦截，及激励视频代跳（随 M5）；
- **部分覆盖 ≈ 25%**：视频贴片（仅破图）、原生广告（可能留白）、内容型素材拦截（随 M6 评估）；
- **未承诺覆盖 ≈ 30%**：短信、平台/搜索/电商广告（评估中），以及程序化 RTB、音频、可试玩广告（技术上不可拦）。

**口径可验证性**：上述百分比是**按广告类型的粗略体感估计**，不是可复算的统计量——清单中「计费方式」等维度本就不构成独立类型（见 4.3），无法把 60+ 条直接求和。公示时**以矩阵条目为准**而非百分比：约 9 类可由 L1 完整或较好解决，约 6 类仅部分覆盖，其余明确不覆盖。**程序化 RTB、音频、可试玩广告**三类须单独提示「技术上不可拦」——这是物理上限而非实现缺陷，承诺任何覆盖率都属于误导。

## 10. 边界解除后的扩展计划

原第 3 节「明确不做」清单解除后，原排除项按下列优先级进入规划池。承接原则：**护栏成熟度优先**——所有新增能力必须过 SafetyGuard 整包黑名单（支付/银行/数字钥匙类不碰）与点击结果校验回退；L2/L3 的发布前置条件（Phase 0 合规评审，见 3.2）不变。

| 序 | 方向 | 层 | 方案要点 | 归属 |
| --- | --- | --- | --- | --- |
| 1 | 激励视频代跳 | L1 | 倒计时后出现「跳过/关闭」控件的样式编写选择器规则，复用 v2 协议与点击校验；支付/银行类整包由 SafetyGuard 兜底 | M5 |
| 2 | 内容型广告素材拦截 | L2 | 信息流/Draw/商店素材域名族扩展进 `filter-rules`；交付形态是「素材拦截后留白」，非「删除节点」——这是无障碍的物理边界 | M6 |
| 3 | 应用商店/搜索广告 | L1+L2 | 商店开屏/弹窗走既有 L1 路径；搜索结果流广告走 L2 素材拦截 | M6 |
| 4 | 短信/彩信营销 | L4 | NotificationListener 启发式扩展到短信通知，默认仅静默、可恢复 | M4 |
| 5 | 视频贴片/Draw | L2 | 维持素材拦截现状，无新增开发 | 持续 |

- M5/M6 采用第 5 节「分版本交付」模式，真机验收口径在启动时补齐，不做大礼包验收；
- 第 9 节公示口径随 M5/M6 交付滚动更新，公示以矩阵条目为准；
- M5/M6 启动前须过 Phase 0 合规复评（李跳跳先例条款持续适用）。
